## Training ML Models for Vision

To detect competition objects, we use ML models to detect them from the camera feed and give us important information that we can calculate such as angle to the object or distance to the object.

### Steps for Training:
- Collect images of the target object. This can be from the sim, a pool test, or a comp run. See BB README on the launch file options that allow you to do so. Usually you want at least 1000-2000 images of the object, at varying levels of lighting and angles so that the model can learn more robustly. Remember, make sure to have good quality training images because garbage in = garbage out.
- Label the images. You can use CVAT (search it up bro) for this purpose, as they have a nice interpolation tool where it allows you to label every other images, and the program automatically interpolates between each frame to semi-automate the labeling process and speed it up by ~2x. You can search up videos on CVAT interpolation to learn how it works, and make sure to set the step size to 2 images per step. Doing more than this in my experience is more unstable and inaccurate for the interpolation.
- Export the image dataset in CVAT to PASCAL VOC format. There is some drop down menus, I trust you to figure this out since I don't feel like typing out the whole thing here. Make sure to check the box to include images when you export the dataset.
- Use this [Google Colab link](https://colab.research.google.com/drive/1FNKsfYtpURg6peZCW8dSWONt6mTi3ksu?usp=sharing) to train the model. You can either upload the .zip dataset file to the colab link and edit the code cells to reflect that, or you can upload it to your drive, mount your drive files following the Colab, and edit the corresponding code cells that way. I trust that you can be able to navigate this. If you're at comp, maybe you could split this up so multiple members each train one model, or if you have a member with a cracked 3090 you could train it locally on a computer using the same code as on the Colab. (Google Colab is an online service where you can run Python code on free GPUs on the cloud provided by Google.)
- Once the model reaches a satisfactory mAP from .5:.95 score (the accuracy score), such as 0.88, you can download the model from the Colab. 
- Then, you can upload the model to Google Drive and edit the corresponding link in models.sh of BB to download the updated model instead. Or, if you're at comp, you can just paste the model inside the folder.
- You're done!

### How the ML Models work

sub_acquisition continually reads images from the front and down cameras and publishes them onto ROS2 topics, while sub_vision continually reads this topic, and every time there is a new image on the topic, sub_vision updates its latest image variable to store that image. Then, when sub_vision receives a vision detection request (eg. from sub_mission), it runs the model on that image. The model outputs the pixel coordinates of the bounding box of the object, given in the xmin (left x value of the box), xmax (right x value of the box), ymin (top y value of the box, since y = 0 is at the top of the image), and ymax (bottom y value of the box) values. Then, we average these values to get the pixel coordinates of the center of the box. 

Then, using formulas developed by alumni Software VP/President Suhas Nagar, we calculate the angles to the object based on the pixel coordinates. Also, copying some stack overflow formulas, we can also calculate the distance to the object (we need to know the ground truth height of the object and some sensor camera parameters first, you can search for where these are defined in sub_vision since I don't feel like typing it all out here). sub_mission then uses this information to do things like turn towards the object, or if it is close enough to the object, go through an object (i.e. gate, buoys) for example.
